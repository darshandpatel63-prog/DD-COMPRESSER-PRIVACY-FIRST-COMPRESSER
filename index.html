How it actually works

Four steps, all of them local. There's no fifth step where anything leaves your device.

  1. 1

    Add a file

    Dropped or picked files are read straight into memory by your browser. DD Compressor never sees a URL to upload to, because it doesn't have one.

  2. 2

    Set a target size

    Pick a goal in KB, MB, or GB. It's a target the engine works toward, not a guarantee — an already-compressed file has less room to shrink, and DD Compressor will tell you so rather than fake a result.

  3. 3

    Compress on your device

    Images use the Canvas API with an iterative quality-and-dimension search. Video and audio run through a local copy of FFmpeg compiled to WebAssembly. PDFs are re-built by recompressing their embedded images, keeping the text layer intact.

  4. 4

    Download the result

    The output is handed to you as a normal browser download. It existed only in this tab's memory before that.

Everything above runs inside this boundary. No upload endpoint exists in this app's code — not ours, not a CDN's, not an analytics provider's. The Content-Security-Policy on this page (view source, or the note below) is set so the browser itself will refuse any attempt to send data out, even a future bug in this code couldn't create a working upload without that policy also being rewritten.
